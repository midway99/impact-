# Карта файлов проекта Impact

## Как читать архитектуру

Проект разделён на четыре основных слоя:

1. `core` создаёт игру и управляет жизненным циклом.
2. `entities` хранит игровые сущности и их состояние.
3. `physics` содержит интеграцию с Havok и отдельную XPBD-физику верёвки.
4. `effects`, `scene`, `input` и `ui` отвечают за отображение, окружение, управление и инструменты разработки.

Главный объект композиции — `Game`: он создаёт зависимости один раз, вызывает системы в нужном порядке каждый кадр и освобождает ресурсы в `dispose()`.

## Точка входа и ядро

| Файл | Ответственность |
|---|---|
| `src/main.ts` | Точка входа. Находит canvas, асинхронно загружает Havok, создаёт `Game`, вызывает `start()` и регистрирует `dispose()` перед закрытием страницы. |
| `src/core/Game.ts` | Корень приложения. Создаёт Engine, Scene и все игровые системы; задаёт порядок одного кадра; запускает render loop; освобождает владельцев ресурсов. |
| `src/core/GameConfig.ts` | Единый типизированный источник игровых чисел: размеры, массы, скорости, цвета, параметры броска, сцены и верёвки. |
| `src/core/BabylonSideEffects.ts` | Регистрирует расширения и шейдеры Babylon, которые не подключаются точечными импортами автоматически. |

### Один кадр в `Game`

`Engine` вызывает рендер сцены, а `Scene` перед рендером запускает `Game.tick()`:

1. `FirstPersonCamera.update()` синхронизирует камеру с игроком.
2. `Grapple.update()` при необходимости тянет игрока к зацепу.
3. Если подтягивания нет, `PlayerController.update()` обрабатывает движение.
4. `ThrowAim.update()` вычисляет точку и скорость броска.
5. `ThrowController.update()` обрабатывает клавишу броска.
6. `TrajectoryPreview.update()` обновляет пунктир будущей траектории.
7. `InspectorToggle.update()` обрабатывает клавишу инспектора.
8. После шага Havok вызываются `Rope.update()` и `RopeRenderer.update()`.

## Игровые сущности

| Файл | Ответственность |
|---|---|
| `src/entities/Player.ts` | Капсула игрока: mesh, Havok-тело, движение, притягивание, reset и освобождение ресурсов. |
| `src/entities/TargetWall.ts` | Статическая физическая стена-мишень; также отдаёт transform и half extents коллайдеру верёвки. |
| `src/entities/ThrowableCube.ts` | Один переиспользуемый куб: запускает тело с заданной скоростью, паркует и телепортирует его обратно. |
| `src/entities/CubePool.ts` | Заранее создаёт набор `ThrowableCube`, общий mesh и материал; при броске выдаёт следующий куб без создания новых объектов. |
| `src/entities/Rope.ts` | Игровая модель верёвки и мост между Havok и XPBD: хранит частицы, запускает конец вместе с кубом, читает положение куба, вызывает solver и ограничивает движение игрока. |
| `src/entities/Grapple.ts` | Машина состояний подтягивания: проверяет закреплённую верёвку и задаёт игроку скорость в сторону точки зацепа. |

## Ввод и бросок

| Файл | Ответственность |
|---|---|
| `src/input/KeyBinding.ts` | Enum с назначенными клавишами игры. |
| `src/input/KeyboardState.ts` | Один раз подписывается на keyboard events, хранит удерживаемые клавиши и одноразовые нажатия. |
| `src/input/CameraAxes.ts` | Вычисляет горизонтальные направления `forward/right` камеры без временных аллокаций. |
| `src/input/PlayerController.ts` | Преобразует WASD в направление относительно камеры и передаёт движение в `Player`; учитывает ограничение верёвки. |
| `src/input/ThrowAim.ts` | Вычисляет origin и velocity броска из позиции игрока и направления камеры. |
| `src/input/ThrowController.ts` | Обрабатывает клавишу броска и cooldown; берёт куб из пула и передаёт его PhysicsBody в `Rope.launch()`. |

### Путь нажатия клавиши броска

`KeyboardState` → `ThrowController` → `ThrowAim` → `CubePool.launchNext()` → `ThrowableCube.launch()` → `Rope.launch()`.

Havok двигает куб, а собственный `RopeSolver` симулирует промежуточные частицы верёвки между рукой игрока и кубом.

## Физика Havok

| Файл | Ответственность |
|---|---|
| `src/physics/HavokPhysicsLoader.ts` | Загружает Havok WASM и создаёт `HavokPlugin`. |
| `src/physics/CollisionGroup.ts` | Битовые группы столкновений и объединённая маска окружения. |
| `src/physics/BodyTeleport.ts` | Безопасно и мгновенно переносит Havok-тело, временно включая pre-step. |
| `src/physics/ImpactFreezer.ts` | Слушает глобальные collision events Havok; при сильном ударе куба о нужную группу останавливает его и делает статичным. |

## Физика верёвки

Верёвка не состоит из множества Havok-тел. Её точки рассчитываются собственным solver, поэтому она дешевле и лучше контролируется.

| Файл | Ответственность |
|---|---|
| `src/physics/rope/ParticleBuffer.ts` | SoA-хранилище частиц в `Float32Array`: position, previous position, velocity и inverse mass. |
| `src/physics/rope/RopeSolver.ts` | XPBD-цикл: substeps, интеграция, ограничения длины/изгиба, столкновения и восстановление скоростей. |
| `src/physics/rope/SelfCollision.ts` | Заранее создаёт пары частиц и раздвигает слишком близкие участки верёвки. |
| `src/physics/rope/RopeCollider.ts` | Интерфейс коллайдера, который solver может подготовить и применить к частице. |
| `src/physics/rope/GroundCollider.ts` | Не позволяет частицам пройти ниже пола и применяет трение. |
| `src/physics/rope/BoxCollider.ts` | Столкновение частиц со стеной: переводит точку в local space коробки, выталкивает наружу и возвращает в world space. |

## Визуальные эффекты

| Файл | Ответственность |
|---|---|
| `src/effects/RopeRenderer.ts` | Читает точки из `Rope`, строит сглаженный путь и обновляет существующий tube mesh только при изменении геометрии. |
| `src/effects/RopeTexture.ts` | Один раз рисует процедурную текстуру и relief верёвки через `DynamicTexture`. |
| `src/effects/TrajectoryPreview.ts` | Считает баллистические точки, делает raycast между ними и выводит пунктир через thin instances; пропускает пересчёт при неизменном aim. |

Важно: `Rope` — модель и физика, а `RopeRenderer` — только отображение. Это позволяет менять внешний вид, не затрагивая solver.

## Владение ресурсами

`Game` владеет верхнеуровневыми объектами. Каждый класс, создающий Babylon-ресурсы или подписки, освобождает их в `dispose()`. Пул кубов владеет всеми кубами; `RopeRenderer` владеет tube mesh, материалом и текстурами; `Arena`, `Player` и `TargetWall` владеют своими mesh и physics aggregate.

Короткая формула проекта:

`main` загружает → `Game` связывает → input отдаёт команды → entities меняют состояние → Havok и RopeSolver считают физику → effects рисуют результат → `dispose()` освобождает всё в обратном порядке.
