# Как устроен проект impact

Карта кода: что за что отвечает, в каком порядке выполняется и где что менять.
Правила разработки — в [AGENTS.md](../AGENTS.md), этот документ описывает устройство.

## Обзор

3D-сцена на Babylon.js: вид от первого лица, персонаж ходит на WASD, по клавише **E**
бросает кубы в сторону взгляда. Перед броском видна траектория полёта.
Физика — Havok (Physics V2), сборка — Vite, язык — TypeScript в строгом режиме.

```bash
npm run dev       # дев-сервер
npm run build     # tsc --noEmit && vite build, должен быть зелёным перед каждым коммитом
npm run preview   # production-сборка локально
```

## Жизненный цикл

### Запуск

1. `index.html` подключает `src/main.ts`.
2. `main.ts` первым делом импортирует `BabylonSideEffects` — иначе часть Babylon не работает.
3. `HavokPhysicsLoader.load()` качает и инициализирует WASM, возвращает `HavokPlugin`.
4. `new Game(canvas, physics)` создаёт движок, сцену, включает физику и собирает все объекты.
5. `game.start()` подписывается на кадр и запускает рендер-цикл.

Физика включается **до** создания сущностей: их тела должны попадать в уже готовый мир.

### Кадр

Порядок задаёт Babylon, и он неочевиден: физика шагает раньше нашего кода.

```
scene.render()
├── scene.animate()
│   └── шаг Havok           тела двигаются, результат переносится в позиции мешей
├── onBeforeRenderObservable
│   └── Game.tick()         ← весь наш игровой код
└── отрисовка
```

`Game.tick()` вызывает системы в явном порядке:

| № | Вызов | Что делает |
|---|---|---|
| 1 | `view.update()` | зажимает взгляд по вертикали |
| 2 | `movement.update()` | читает WASD, задаёт персонажу скорость |
| 3 | `aim.update()` | считает точку вылета и скорость броска |
| 4 | `throwing.update(dt)` | проверяет нажатие E, запускает куб |
| 5 | `trajectory.update()` | перерисовывает пунктир |

Скорость, заданная на шаге 2, применится на следующем шаге физики — наш код выполняется
уже после неё. Это нормальная задержка в один кадр.

## Слои и зависимости

| Слой | За что отвечает | Кого знает |
|---|---|---|
| `core/` | движок, цикл, конфиг | всех |
| `scene/` | камера, свет, пол | конфиг, `Player` |
| `entities/` | объекты мира: меш + тело + поведение | конфиг, `physics/` |
| `input/` | клавиатура и мышь → методы сущностей | сущности |
| `effects/` | визуал поверх игры | сущности, конфиг |
| `physics/` | загрузка движка, группы, утилиты | ничего из игры |

Зависимости идут только сверху вниз. `physics/` не знает про игру, `entities/` не знают
про ввод, `input/` не трогает физические тела напрямую — только методы сущностей.

## Подсистемы

### Сцена и камера

`Arena` создаёт направленный свет (основной), полусферический (заполняющий) и пол
со статичным телом. Игровых объектов не знает.

`FirstPersonCamera` — `UniversalCamera`, привязанная через `parent` к капсуле персонажа:
её везёт физика, а не ввод. Клик по сцене захватывает мышь (pointer lock), `Esc` отпускает.
Взгляд по вертикали ограничен `maxPitch`. У камеры **удалён штатный WASD**
(`inputs.removeByType("FreeCameraKeyboardMoveInput")`) — иначе она двигалась бы сама,
сквозь стены и мимо физики.

### Персонаж и управление

`Player` владеет капсулой, материалом и телом Havok. Момент инерции обнулён, поэтому
персонаж не заваливается набок. Меш скрыт: камера сидит внутри капсулы.

`move(direction)` подменяет горизонтальную скорость тела и не трогает вертикальную —
за падение отвечает гравитация.

`PlayerController` складывает оси камеры по нажатым клавишам, нормализует диагональ
(иначе по диагонали скорость была бы в 1.41 раза выше) и вызывает `player.move()`.
Направление берётся от камеры, спроецированной на пол: смотришь в пол — идёшь с той же скоростью.

`KeyboardState` различает два вида ввода:

- `isPressed(code)` — клавиша удерживается сейчас (движение);
- `consumePress(code)` — было нажатие с прошлой проверки, проверка его «съедает» (бросок).
  Ловит короткий тап, когда нажатие и отпускание уложились между кадрами.
  Автоповтор зажатой клавиши новым нажатием не считается.

### Броски и пул кубов

`CubePool` при старте создаёт 12 кубов: общая геометрия и материал, каждый куб — инстанс.
Выдаёт их по кругу, поэтому 13-й бросок переиспользует куб от первого.
Во время игры ни одного `new` и ни одного `dispose`.

`ThrowableCube` живёт в двух состояниях:

| Состояние | Тело | Меш | Где |
|---|---|---|---|
| `park()` | статичное | скрыт | `parkPosition (0, −50, 0)`, под полом |
| `launch()` | динамическое | виден | у руки, со скоростью броска |

`ThrowAim` считает, откуда и с какой скоростью полетит куб: точка вылета — перед
персонажем (чтобы куб не родился внутри капсулы), направление — полное направление
взгляда, плюс подъём `lift` для дуги. Это единственный источник данных и для самого
броска, и для пунктира, поэтому они не могут разойтись.

`ThrowController` ловит нажатие и держит перезарядку.

### Пунктир траектории

`TrajectoryPreview` шагает по параболе `p = p₀ + v·t + g·t²/2` с шагом `timeStep`
и на каждом отрезке пускает луч Havok. При попадании последняя точка ставится в место
удара, и дуга обрывается. Лучи фильтруются по группам коллизий и видят только пол и стену,
поэтому летящие кубы прицел не обрывают.

Все точки — thin instances одной сферы: один вызов отрисовки, буфер матриц выделен заранее.

### Физика

Havok подключается через `HavokPhysicsLoader`: WASM импортируется как URL (`?url`),
иначе в production-сборке файл не находится. Havok исключён из `optimizeDeps` в
`vite.config.ts` — пре-бандл esbuild ломает поиск WASM.

Каждая сущность владеет своим `PhysicsAggregate` — это связка «меш ↔ тело», которая
разом создаёт тело, форму столкновений и физический материал.

Тела в проекте:

| Объект | Тип | Масса |
|---|---|---|
| Пол | статичное | 0 |
| Стена | статичное | 0 |
| Персонаж | динамическое, капсула, без вращения | 5 |
| Куб | динамическое, коробка | 1 |

`CollisionGroup` задаёт битовые маски групп. Важно: по умолчанию у тела «все биты»,
поэтому фильтрация работает, только если группа выставлена каждому телу явно.

`BodyTeleport` переносит тело в точку. Синхронизация «меш → тело» (pre-step) по умолчанию
выключена, и Havok отказывается телепортировать такое тело. Поэтому pre-step включается
на время вызова и сразу выключается: если оставить включённым, физика каждый шаг будет
тянуть тело к мешу, и объект зависнет в воздухе.

## Конфигурация

Все числа — в `GameConfig.ts`, типизированы интерфейсами.

| Секция | Что настраивает |
|---|---|
| `clearColor`, `gravity`, `parkPosition` | фон, гравитация мира, место хранения тел из пулов |
| `camera` | высота глаз, чувствительность мыши, предел взгляда, ближняя плоскость |
| `light` | направление и яркость обоих источников |
| `ground` | размер, цвет, тело пола |
| `player` | габариты капсулы, спавн, скорость, тело |
| `wall` | габариты, позиция, тело стены |
| `throwable` | размер куба, размер пула, скорость и дуга броска, перезарядка |
| `trajectory` | число точек, размер, шаг по времени, цвет |

Общий тип `BodyConfig` (`mass`, `friction`, `restitution`) совпадает по форме с параметрами
`PhysicsAggregate` и передаётся в него напрямую — параметры не дублируются.

## Производительность

Бюджет кадра — 16 мс, и главный враг здесь сборщик мусора: пауза сразу видна как рывок.
Правила и то, как они соблюдаются:

- **Ноль аллокаций в кадре.** Векторы — поля класса, операции через методы `*ToRef`.
- **Колбэки создаются один раз** как поля класса, а не стрелки внутри `update()`.
- **Подписки** вешаются при инициализации и снимаются в `dispose()`.
- **Пулы** вместо создания и удаления: кубы существуют всё время жизни сцены.
- **Инстансы** вместо копий мешей: 12 кубов и 40 точек пунктира рисуются почти за один вызов.
- **Циклы `for`** по индексу вместо `map`/`filter` в горячем пути.

## Ловушки Babylon, на которые уже наступали

| Симптом | Причина | Лечение |
|---|---|---|
| `X needs to be imported before` | не подключён модуль с побочным эффектом | добавить импорт в `BabylonSideEffects.ts` |
| Чёрный экран, в консоли `'<' : syntax error` и `<!doctype html>` в шейдере | шейдера нет в `ShaderStore`, Babylon качает его по HTTP и получает `index.html` | импорт шейдеров там же |
| `Prestep type is set to DISABLED. Unable to set physics body transformation` | тело нельзя телепортировать с выключенным pre-step | `BodyTeleport` |
| Объект завис в воздухе, гравитация не действует | pre-step остался включённым | выключить сразу после переноса |
| Объект пропадает при повороте камеры | габариты исходного меша не описывают инстансы | `alwaysSelectAsActiveMesh = true` |
| Короткое нажатие клавиши теряется | `keydown` и `keyup` уложились между кадрами | `KeyboardState.consumePress()` |
| WASM не грузится в production | путь к файлу потерян сборщиком | импорт через `?url` и `optimizeDeps.exclude` |

## Известные ограничения

- Персонаж не умеет прыгать; нет проверки «стоим на земле».
- Тело персонажа не поворачивается за камерой — визуально незаметно, пока капсула скрыта.
- Стена статична: её нельзя сбить. Если понадобится разрушаемая мишень, её делают кладкой
  из отдельных тел, а не одним блоком.
- Пунктир при взгляде прямо превращается в пятно в центре экрана: парабола видна с торца.
